<p>关于注册用住宅 IP，真正被反复问的其实只有四个问题：ISP 住宅和普通住宅差在哪、为什么非要每个号独立环境、试用到底怎么试、什么时候该转包月。这四个问题一个接一个，答不上第一个就没必要谈第二个。这篇按顺序串下来，每个问题给判断依据和可执行动作，最后给一张试用期的检查表。</p>
<h2>一、第一个真问题：ISP 住宅 IP 和普通住宅 IP 差在哪</h2>
<p>差在出口的登记主体。ISP 住宅 IP 的 ASN 直接登记在电信运营商名下，地址段与普通家庭宽带混在一起；普通住宅 IP 有时是聚合多户家庭网络，出口可能落在中间服务商手里，登记信息看起来就不是运营商。</p>
<h3>为什么登记主体重要</h3>
<p>因为它是唯一能公开查证的信息。平台看到的不是你说了什么，而是 ASN、whois、反向解析这些硬记录。登记主体是运营商，说明这条线大概率真的接在某户人家的宽带上；登记主体是中间商，说明中间还隔了一层，稳定性和归属都可能不如预期。</p>
<h3>三分钟查清的办法</h3>
<p>拿 IP 去 bgp.he.net 看 origin AS 的机构名，去 ipinfo.io 看 org 与 asn 字段，再 dig -x 看有没有运营商域名的 PTR。三项一致指向 Comcast、Verizon、AT&T、Deutsche Telekom、Orange 这类运营商，就可以认为符合 ISP 住宅的特征。</p>

<h2>二、第二个真问题：为什么每个号要独立环境</h2>
<p>因为环境是账号的「住处」。两个号住同一个房间，留下的痕迹就会互相指向。独立环境不只是换 IP，还包括浏览器配置目录、Cookie、本地存储、时区语言这些一起独立。</p>
<h3>独立到什么程度才算独立</h3>
<p>四项必须分开：出口地址、浏览器配置目录、Cookie 与本地存储、登录凭据。四项里少一项，两个号之间就有一条可见的联系。物理机器和操作系统可以共用，前提是每项都有独立的目录与实例。</p>
<h3>常见的「假独立」</h3>
<p>同一浏览器切用户配置但共用缓存目录；同一台机器用容器但挂载同一个临时目录；换 IP 但时区语言没变。这三种看起来做了隔离，实际留着明显的关联线索，属于花了成本没买到效果。</p>

<h2>三、第三个真问题：试用怎么试才算试过</h2>
<p>试用不是「能连上就算过」。真正的试用要覆盖三个维度：连通性、纯净度、连续性。三个维度各有一到两个可量化指标，跑满五到七天再下结论。</p>
<h3>五到七天怎么排</h3>
<p>第一天打通并记录基线，第二到四天观察夜间表现，第五天做一次出口一致性核查，第六到七天跑接近真实业务的负载。整个周期不长，但足够暴露大部分问题。时间太短的试用，只能证明「付款后能连」，证明不了别的。</p>

<h2>四、第四个真问题：什么信号说明该转包月</h2>
<p>转包月的判断标准是用量稳定且长期在线，而不是「试用感觉不错」。三个信号同时出现才转：连续两周日均在线超过八小时、月流量折算已经超过平衡点、号码进入长期维护状态不再频繁调整。</p>
<h3>算一个平衡点再决定</h3>
<p>包月单价除以按量单价，得到每月至少要用的量。举个思路性的例子：包月五十元、按量每 GB 两元五角，平衡点是二十 GB；你实际每月只用六 GB，那按量明显更划算。算清楚再签，别凭「包月听起来省心」下单。</p>
<h3>转包月时别一次买满</h3>
<p>先按当前用量的六到七成买，留出增长空间，按月调整。一次买满看似省事，实际是把闲置成本固定下来，而且服务商一旦出问题，退订谈判会更被动。</p>
<h2>常见问答</h2>
<h3>ISP 住宅 IP 一定比聚合住宅稳吗？</h3>
<p>答：通常更稳，但不绝对。稳定性还取决于这条线上游的带宽和运维水平。判断方法是看七天探活数据，而不是看类型标签。标签只是起点，数据才是结论。</p>
<h3>一个号需要一条独立 IP 吗？</h3>
<p>答：需要长期登录、需要稳定地区归属的号，建议一条一条对应。只做读取、不保留登录态的任务，可以共用或轮换。是否独立，取决于业务对连续性的要求，不取决于数量。</p>
<h3>试用期发现延迟高，能直接退吗？</h3>
<p>答：看合同。正规服务商通常给三到七天无理由更换或退订窗口，超出窗口一般只能按剩余天数折算。下单前把这条问清并留下书面记录，比事后争论有效得多。</p>
<h3>包月中途想改成按量，可以吗？</h3>
<p>答：多数服务商支持到期后切换，中途切换较少见。真要中途改，先确认已用部分如何计费、剩余金额是否可结转。这两点不问清，切换时容易产生额外费用。</p>
